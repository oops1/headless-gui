# ADR-0003. Общий глиф-кэш процесса

Статус: принято 2026-10-28 после состязательной проверки проекта (4 линзы, 14
замечаний) и ревью кода (4 измерения, 8 различных замечаний — все учтены), ветка `feature/engine-architecture`,
работы к 4.0 (этап 4, задача 4.2). Основание —
`docs/ARCHITECTURE_REVIEW_RU.md`, §4 (Р9) и §3 («несколько движков в одном
процессе — норма»).

## Контекст

Каждый движок держит свои шрифты целиком: `engine.New` разбирает основной
шрифт, встроенные жирный/курсив/моно и, лениво, запасную цепочку; каждый
`core/text.FontCache` хранит разобранный `opentype.Font`, typesetting-face и
кэши — `font.Face` по кеглю, маски глифов по (кегль, руна, фаза), кернинг,
метрики, зоны хинтинга, наличие глифа в cmap. Движков в процессе много:
Tandem создаёт по движку на монитор, WinLine — hosted-диалоги, оторванные
панели, второй стол и движок на каждое задание печати. Один и тот же глиф
растеризуется и хранится столько раз, сколько движков его нарисовали;
память и время старта растут линейно.

Что уже общее на процесс: содержимое файлов шрифтов (`ReadFontFile`), таблицы
контраста (`ContrastLUT`). Что мешает делить остальное:

- `opentype.Face` (x/image) и `tsfont.Face` (typesetting) **не
  потокобезопасны** — у обоих внутренние буферы и кэши; `sfnt.Font` и
  `tsfont.Font` безопасны (с отдельным `sfnt.Buffer` на вызов).
- Измерение зовёт `face.GlyphAdvance`/`Kern` **без замка**: `Measure` — у
  холста без запасных шрифтов, `runeAdvance` (`core/raster/canvas.go`) — у
  боевого холста после `AddDefaultFonts`. Горутина приложения
  (`widget.MeasureUIText` → `canvas.MeasureText`) и горутина кадра
  (`drawTextWithFont`, `ctx.MeasureText` внутри `Draw`) делят один
  `opentype.Face`. Внутри одного движка это скрытая гонка; при общем кэше она
  стала бы гонкой двух движков.
- Личный `tsfont.Face` вида делят шейперы всех клонов холста (`CloneForSize`,
  оверлей попапа, временный холст `DrawTextRotated`), у каждого клона свой
  `Shaper.mu`; измеритель зовёт `Layout` основного холста параллельно с
  кадром, рисующим RTL-строку в попапе, — гонка на `cmapCache`/`extentsCache`.
- Ключ кэша масок не содержит DPI, подпиксельный режим и качество: они —
  состояние `FontCache`, и их смена сбрасывает кэш целиком. У двух движков с
  разным DPI общий кэш обязан различать маски ключом.

## Решение

### Два уровня: личный L1 вида и общий L2 процесса

```
glyphStore (процесс)            бюджет байт, часы, индекс шрифтов, вытеснение
└── fontData (на содержимое)    разобранный sfnt.Font, tsfont.Font (лениво),
    │                           scratch tsfont.Face под shapeMu, есть ли цвет
    ├── shard (шрифт, кегль)    L2: маски, шаги, кернинг, метрики, зоны хинтинга;
    │                           scratch opentype.Face по (DPI, подпиксель), буфер,
    │                           растеризатор — всё под shard.mu
    └── shapedShard (шрифт, px) L2 шейпера: маски и цветные глифы по GID, зоны

FontCache (вид: одна регистрация в холсте)
    font *fontData + {DPI, подпиксель, качество} под fc.mu
    L1: glyphs/kern/metrics/adv с ПРЕЖНИМ ключом (кегль, руна, фаза) — как сегодня
    glyphPresent + свой sfnt.Buffer (HasGlyph), личный font.Face для Face(),
    личный tsfont.Face для раскладок, famKey
```

Горячий путь попадания (`drawTextWithFont` → `PenGlyph` → `GlyphAt`,
`Kern`, `VMetrics`) **не меняется**: `fc.mu.RLock` + та же map с 16-байтным
ключом, замок личный для движка, кэш-линии между движками не делятся. L1
хранит значения `CachedGlyph`, указывающие на те же маски, что лежат в L2;
лишней памяти нет. L1 ограничен числом записей (`maxGlyphCacheEntries`,
`maxKernCacheEntries`) и сбрасывается в `SetDPI`/`SetSubpixel`/`SetQuality`,
как сегодня. Хранилище трогается только на промахе L1: `shard.mu.RLock` →
ключ с параметрами вида → при промахе растеризация под `shard.mu.Lock` и
вставка в L2, затем в L1.

`FontCache` остаётся публичным типом с прежними методами (`engine.FontCache`
— его алиас).

### Интернирование шрифта

`NewFontCacheFromData(data, dpi)`:

- `len(data) == 0` → `nil` до любого обращения к индексу;
- быстрый путь — по адресу и длине среза, но в адресном индексе хранится
  **только канонический срез** `fontData` (тот, из которого он разобран и
  который держит `sfnt.Font`): `ReadFontFile` и пакетные переменные
  `gofont/*` отдают один и тот же срез каждому движку, и движок-на-диалог
  попадает в него; адрес канонического среза не может быть переиспользован,
  пока `fontData` жив;
- любой другой адрес (копия из `LoadFontFile`, `RegisterFontFS`, `embed`,
  `append`) — `maphash` по байтам и `bytes.Equal` с кандидатом **при каждой
  регистрации**, без записи в адресный индекс: копия отдаётся GC сразу после
  регистрации (0,8 МБ ≈ 0,1 мс; 20 МБ ≈ 5 мс — цена регистрации, не кадра);
- поиск и вставка — под `store.mu`, разбор (`maphash`, `bytes.Equal`,
  `opentype.Parse`) — **вне** его; после разбора повторный поиск под
  `store.mu`: если конкурент уже вставил `fontData` для тех же байт, свой
  экземпляр отбрасывается. Двойной разбор при гонке допустим, двух
  `fontData` на одни байты не бывает;
- невалидные данные не интернируются (`nil`, как раньше).

`tsfont.ParseTTF` — лениво, при первом шейпинге, один раз на `fontData`.
Индекс ограничен (`maxInternedFonts` = 256 по содержимому): при переполнении
выбывает шрифт, который дольше всех не искали; живые виды продолжают держать
свой `fontData`, его шарды остаются ограничены своими лимитами, а повторная
регистрация такого шрифта разберёт его заново.

### Ключи L2

Шард — `(fontData, кегль в пунктах)`. Внутри шарда:

| кэш | ключ | зависит от |
|---|---|---|
| `faces` (scratch) | `faceKey{dpi, subpixel}` | хинтинг x/image зависит от подпикселя |
| `glyphs` | `faceKey + rune + phase + TextQuality` | маска: DPI, фаза, хинтинг, LCD, порядок |
| `adv` | `faceKey + rune` | шаг глифа (`GlyphAdvance`) |
| `kern` | `faceKey + a + b` | кернинг пары |
| `metrics` | `faceKey` | подъём, спуск, зазор |
| `hints` | `dpi` (→ ppem) | зоны автохинтера |

`TextQuality` в ключе — нормализованный (`normalized()`), сравнимый struct.
Контраст в маску не входит (он — таблица при блите), но остаётся в ключе
ради простоты; лишних масок он не плодит, потому что у холста одно значение.
Стоимость хэша длинного ключа платится только на промахе L1.

Шард шейпера — `(fontData, размер в px 26.6)`: маски по `(GID, hint)`,
цветные глифы по `GID`, цветозависимые — по `(GID, цвет)`, зоны хинтинга —
одна на шард. **Владелец** face известен раскладке: `chainFontmap` строит её
из видов (primary ↔ `fc`, запасные ↔ `fb.Get(ref)`), поэтому `PlacedGlyph`
несёт указатель на свой шард (`*shapedShard`, разрешается один раз при
построении раскладки) рядом с `Face`, а `GlyphMaskFor`/`ColorGlyphFor`
принимают глиф раскладки: на пути глифа — один замок шарда, как раньше
`Shaper.mu`. Индекс хранилища не трогается; «постороннего» face не бывает.
Растеризация — scratch-`tsfont.Face` шрифта под `fontData.shapeMu` (один на
шрифт); перед каждым обращением к нему выставляется ppem размера шарда
(`setPpemFor`): растровые страйки и экстенты зависят от ppem, а face общий
для всех размеров и движков. Признак «у шрифта есть цветные глифы» —
атомарный флаг `fontData` (вычисляется при разборе typesetting), и для
монохромного шрифта `ColorGlyphFor` отвечает `nil` без замков и без записи.

### Шейпер — один на линию клонов

`Canvas.shaper` становится указателем; `adopt` (`CloneForSize`,
`CloneForPhys`) и временный холст `DrawTextRotated` берут шейпер исходного
холста. Все обращения к личному `tsfont.Face` вида идут под одним `Shaper.mu`
— гонка измерителя с кадром попапа закрыта. Раскладки (`Layout`, ключ — вид,
кегль, текст) остаются у шейпера, `DropLayouts` при `SetDPI`/`SetSubpixel` —
как сегодня.

### Замки и инварианты

- **И1 (чистота ключа).** Растр глифа — функция ключа L2 и только его: байты
  шрифта, кегль, DPI, подпиксельная фаза, качество. Ничего из состояния
  холста или движка в маску не входит (`plainText` повёрнутого текста меняет
  лишь таблицу контраста при блите). Поэтому маску, снятую одним движком,
  другой блитит как свою; записи, оставшиеся от чужих тестов, результат не
  меняют.
- **И2 (небезопасные объекты — под write-замком владельца).**
  `opentype.Face`, `sfnt.Buffer`, `vector.Rasterizer` шарда — только под
  `shard.mu.Lock`; scratch-`tsfont.Face` шрифта — только под
  `fontData.shapeMu`; на промахе замки берутся с `defer`: паника
  растеризатора на битом шрифте уходит в границу кадра (`FailureIsolate`),
  а общий шард не остаётся захваченным для остальных движков; личный `tsfont.Face` вида — только под `Shaper.mu`
  (единственного на линию клонов). Опубликованные `CachedGlyph`, `GlyphMask`,
  `ColorGlyph` неизменяемы и читаются без замка. Публичный
  `FontCache.Face(sizePt)` возвращает **личный** face вида (как и раньше — не
  для одновременного использования); его кэш очищается при каждом `Set*`,
  как сегодня; **ни один внутренний путь** `core/raster` и `engine` вне
  тестов его не зовёт (`runeAdvance`, `measureRunePositionsPxFont` → `Advance`).
- **И3 (измерение без face).** `Measure`, `MeasureRunes`, `Kern`,
  `Advance`, `VMetrics` читают L1 под `fc.mu.RLock`, L2 под `shard.mu.RLock`;
  промах считает под `shard.mu.Lock`. Гонка измерителя с кадром закрыта на
  обоих путях — per-rune и шейпера.
- **И4 (порядок замков).** `Shaper.mu → FallbackFont.mu → fc.mu → store.mu`,
  `fc.mu → shard.mu → fontData.shapeMu`, `store.mu → shard.mu` (вытеснение);
  обратных рёбер нет: вытеснение не трогает `FallbackFont`, `Shaper` и виды,
  разбор шрифта идёт вне `store.mu`. Учёт байт, `clock` и `shard.lastUse` —
  атомарные (`Load`/`Store` без CAS; потеря обновления `lastUse` допустима —
  влияет только на порядок вытеснения). Вытеснение вызывается **после**
  отпускания `shard.mu`.
- **И5 (ёмкость).** `bytes ≤ budget` после каждой вставки с точностью до
  параллельных вставок; после вытеснения `bytes ≤ budget/2`. Бюджет по
  умолчанию `DefaultGlyphCacheBudget` = 64 МиБ, задаётся
  `text.SetGlyphCacheBudget` (`engine.SetGlyphCacheBudget` — обёртка). Учёт
  шарда — единственный источник правды: хранилище получает **дельту** учёта
  шарда на каждом промахе (вставка, зоны хинтинга, переполнение), поэтому
  сумма учётов шардов индекса равна учёту хранилища на любом пути. Шард
  дополнительно ограничен числом записей (`maxShardGlyphs` = 8192 масок,
  `maxShardSmall` = 16384 шагов и кернинга, при переполнении очищается) —
  это держит и шрифты, выбывшие из индекса: такой шрифт помечается
  `detached`, его шарды очищаются и снимаются с учёта, дальше он бюджета не
  касается и живёт под лимитами записей. L1 может удерживать маски, уже
  вытесненные из L2; этот довесок ограничен лимитами L1, как сегодняшний
  кэш.
- **И6 (кэш не знает о движках).** `Engine.Stop` кэш не трогает; вид умирает
  вместе с холстом как обычный объект, копии байт шрифта — сразу после
  регистрации; общие записи живут, пока их не вытеснил бюджет. Второй движок
  после `Stop` первого продолжает попадать в те же маски.

### Вытеснение

Часы хранилища (`clock`) идут на каждом промахе L2. Попадание L2 обновляет
`shard.lastUse`, только если оно отстало от часов. Когда учёт байт превысил
бюджет, под `store.mu` шарды обоих видов всех шрифтов индекса сортируются по
`lastUse` и очищаются от самых старых, пока не останется ≤ budget/2. Шард
остаётся в таблице шрифта (новые кегли — редкость, таблица под
`fontData.mu`); очищается его содержимое, включая scratch-face. Учёт: маска —
длина `Pix` + 64 байта; LCD-маска — её `Pix` + 64; шаг/кернинг — 32;
метрики — 32; зоны — 256; цветной глиф — длина `Img.Pix` + 64. Шарды
шрифта, выбывшего из индекса, в вытеснении не участвуют и бюджет не
заряжают — их держит лимит записей.

### Что не меняется

Публичный API `engine` и `widget`; сигнатуры методов `FontCache`
(`Face`, `Glyph`, `GlyphAt`, `Kern`, `Measure`, `MeasureRunes`, `VMetrics*`,
`HasGlyph`, `Set*`, `Quality`, `Subpixel`, `DPI`, `PixelSize`, поле `TTF`);
`FontTable`, `FontFamilies`, `FallbackFont`; `Shaper.Layout`, `DropLayouts`,
`CacheSizes`. Побайтовый вид текста (golden, `TestTextQuality_MaskHash`) не
меняется: растеризация та же, изменилось только где лежит результат.
`engine/svgtext.go` работает с `fc.TTF` (общий `sfnt.Font`) через свой
`sfnt.Buffer` — безопасно.

Новое в `core/text`: `Advance(sizePt, r) (fixed.Int26_6, bool)` (кэш L1/L2;
`ok` — как у `GlyphAdvance`, подмена пробела для непокрытой руны остаётся
решением `runeAdvance` по `found` из cmap); `GlyphMaskFor(g PlacedGlyph,
sizePx, hint)`, `ColorGlyphFor(g PlacedGlyph, sizePx, col)`;
`SetGlyphCacheBudget`, `DefaultGlyphCacheBudget`, `GlyphCacheStats` (шрифты
в индексе, шарды, записи, байты), `ResetGlyphCache` (очищает записи L2 и
индекс не трогает; `testreset.Reset` зовёт его и возвращает бюджет по
умолчанию).

## Отвергнутые варианты

- **Только общий кэш без L1 вида.** Два движка на одном шарде делили бы
  кэш-линию `RWMutex` на каждом глифе (`RLock` пишет счётчик читателей) и
  платили бы хэш 40-байтного ключа на каждое попадание — регрессия
  `DrawText` при параллельных кадрах. L1 с прежним ключом делает горячий
  путь тождественным сегодняшнему.
- **Слабые ссылки (`weak`, `runtime.AddCleanup`) на `fontData`** — чтобы
  шрифты мёртвых движков собирал GC. Требует `go 1.24` в `go.mod` (сейчас
  `go 1.22.0`, `stdversion` в vet ругался бы), а бюджет и лимиты и так
  ограничивают память; индекс с лимитом проще и детерминирован.
- **Подсчёт ссылок с `Close` у движка.** У `FontCache` нет владельца: холсты
  клонируются, таблицы шрифтов общие у клонов, виды раздаются измерителю
  процесса. Любая ошибка счётчика — либо утечка, либо удаление из-под живого
  вида.
- **Адресный индекс на каждую копию байт.** Удерживал бы каждую копию
  (печать Блокнота: ~1,6 МБ на задание навсегда). Хэш копии при регистрации
  дешевле.
- **Искать владельца маски шейпера по `face.Font` через индекс.** Замок
  хранилища на каждом глифе и потеря кэша у шрифта, выбывшего из индекса.
  Раскладка и так знает владельца.
- **Шард по `(шрифт, кегль, DPI, подпиксель)`** вместо ключа в записи.
  Эквивалентно по памяти; с L1 разницы в скорости нет, а ключи с
  DPI/качеством/подпикселем названы в плане явно.

## Приёмка

1. Два движка рисуют один текст: маски `DefaultFont().Glyph(...)`
   указательно равны; дельта `GlyphCacheStats` после второго движка — ноль
   записей. `SetDPI(120)` у второго — записи различаются; `Stop` первого —
   указатели и статистика у второго прежние.
2. `-race`: два движка рендерят одновременно (в одном из них попап с
   RTL-строкой), третья горутина меряет текст обоих (`MeasureText` строки с
   руной из запасного шрифта «✓» и RTL-строки, `MeasureTextFont`), четвёртая
   регистрирует шрифт из копии байт.
3. Бюджет: при `SetGlyphCacheBudget(256 КиБ)` после прогона всех букв
   алфавитов в пяти кеглях `bytes ≤ budget`, кадр побайтно равен кадру с
   бюджетом по умолчанию.
4. Интернирование: 1000 регистраций `append([]byte(nil), data...)` — число
   шрифтов в индексе прежнее, `HeapInuse` после `runtime.GC` не растёт сверх
   одного комплекта; `RegisterFont(name, nil)`, `RegisterFont(name,
   []byte{})`, `AddFallbackFont([]byte{})` — без паники и без записи в индекс.
5. Бенчмарки без регрессии на попадании: `DrawText`, `DrawTextShaped`,
   `TextInputDrawCached`, `KernCached`, `Pipeline_*`; новый
   `DrawTextTwoEngines` (два движка параллельно, один шрифт и кегль) — не
   хуже `DrawText` на поток; `EngineNew` ожидаемо быстрее (разбор один раз).
   Промах L2 (`GlyphRasterLegacy/Hinting` — чистый путь промаха) дороже на
   две вставки (L2 с длинным ключом и L1) и учёт — ~150 нс на глиф сверх
   растеризации (~750 нс); это принятая цена: промах теперь один на процесс,
   а не на движок.
6. Матрица репозитория зелёная; golden без регенерации; `grep` подтверждает,
   что `FontCache.Face(` вне тестов зовут только `core/text`.
