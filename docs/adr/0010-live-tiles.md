# ADR-0010. Живые плитки

Статус: принято 2026-10-29, реализовано в 6.1–6.4, ветка
`feature/engine-architecture` (этап 6). Основание — план этапа 6 и
`docs/ARCHITECTURE_REVIEW_RU.md` §5.3: «`TileSource` — интерфейс потребителя,
`LiveTile` держит очередь состояний и перебирает их по `tile.cycle`;
подписка живёт, только пока меню открыто: закрыто — ни кадров, ни вызовов;
обновления — через `Post`».

## Контекст

Плитка меню «Пуск» (презентер `tiles`, профиль Windows 10) показывает
`TileContent`, который потребитель меняет вызовом `StartMenu.SetTileContent`.
Живого содержимого (часы, погода, почта, календарь) у меню своего нет:
потребитель должен сам держать таймеры, знать, открыто ли меню, и не будить
кадры закрытого. На практике такой код будит движок и при закрытом меню —
источник тикает всегда.

## Решение

Публичные типы `desktop`:

```go
type TileSource interface {
	Subscribe(fn func(TileContent)) (unsubscribe func())
}

type LiveTile struct {
	Source TileSource
	Queue  int           // сколько последних состояний перебирать; 0 — 5
	Period time.Duration // пауза между состояниями; 0 — по умолчанию
}

type Tile struct { …; Live LiveTile }
```

и поле `StartMenu.Post func(func())` — перенос обновлений в поток
интерфейса (`Engine.Post`), как у `ScreenBars.Post`. Без него обновления идут
в поток движка, которому принадлежит дерево меню: новая служба владельца
`widget.PostFor(w, fn)` (`OwnerPoster`, у движка — `Post`). Меню вне дерева
движка обновляется на месте.

`LiveTile` — значение, а не объект с состоянием: плитки копируются
(`TileGroups`, `OnTilesChanged`), а меню на каждом мониторе своё. Состояние
живой плитки (очередь, показанное, таймер перебора, отписка) держит меню в
`liveSet` под собственным замком — `Draw` читает показанное, не трогая замок
модели.

Жизненный цикл:

- Подписки оформляются в `afterOpen` и только у меню с плитками (`tiled`):
  у Windows 11 и плоского меню плиток нет, источник не зовётся.
  Снимаются в `afterClose` (`Flyout.Close` — Esc, клик мимо, соседняя
  панель), то есть закрытое меню источник не вызывает и кадров не будит.
  Открытость проверяется под замком живых плиток: `Close` сбрасывает флаг до
  отписки, и смена плиток с другой горутины подписку закрытому меню не
  оставит.
- Смена плиток (`SetTileGroups`) и темы на открытом меню сверяет подписки с
  плитками: плитка с тем же источником сохраняет подписку, очередь и
  показанное (состояние, уже поставленное в `Post`, не теряется); у плитки со
  сменившимся источником состояния прежнего сброшены; вид без плиток снимает
  подписки, но показанное хранит до возвращения плиток. Источник с
  несравнимым динамическим типом (`TileSourceFunc`) считается новым.
- У каждой плитки номер подписки (`sub`) и номер шага таймера (`tick`).
  Состояние от снятой подписки (источник позвал fn в гонке с отпиской) и
  шаг остановленного таймера отбрасываются, не доходя до `Post`.
- После подписки первое состояние начинает очередь заново (источник обычно
  сразу присылает текущее, повтор не должен копиться в очереди), а до него
  плитка показывает прежнее — без мигания при повторном открытии.
- Новое состояние встаёт в конец очереди и показывается сразу; старше
  `Queue` — отбрасываются. При двух и более состояниях таймер перебирает их
  с периодом `Period`.
- Обновление заявляет только прямоугольник плитки (`InvalidateArea`), а не
  всё меню.

`SetTileContent` меняет содержимое по умолчанию (`Tile.Content`): его плитка
показывает, пока от источника ничего не пришло. Состояния источника в модель
(`TileGroups`) не попадают.

## Переход между состояниями (6.2)

Смена показанного состояния (новое от источника или шаг перебора) заводит
переход `AnimTileCycle` (`tile.cycle`; не объявлен темой — по
`flyout.open`). Вид — метрика `tile.cycle.kind`: 0 — сдвиг (новое въезжает
снизу и выталкивает прежнее вверх), 1 — переворот вокруг горизонтальной оси
(прежнее сжимается к середине, затем раскрывается новое).

- Кэш растра. В первом кадре перехода прежнее и новое содержимое плитки
  рисуются вне кадра в две картинки на прозрачном фоне — новая возможность
  контекста `OffscreenRenderer` (`core/draw`, алиас в `widget`), её реализуют
  холст (`Canvas.RenderOffscreen`: своё окно, всегда RGBA с альфой, каким бы
  ни был формат кадра) и рекордер команд (через холст). Кадры перехода только
  компонуют две картинки (`DrawImageRect`, у сдвига 1:1 ближайшим пикселем)
  в клипе плитки; текст и значок заново не рисуются. Картинки
  перерисовываются, если сменился размер плитки или её состояние (наведение),
  при смене темы или плиток (`liveAttach`), а пока идёт переход цвета
  наведения, не хранятся вовсе — стиль меняется каждый кадр.
- Обёртки контекста пробрасывают возможность: `translatingContext` арены
  попапов (меню в окне ОС — настоящее окно всегда ставит `SetPopupSink`) и
  `OffsetContext` прокрутки сдвигают область и отдают draw контекст картинки
  с тем же сдвигом.
- Перехода нет у первого состояния новой подписки (повторное открытие меню) и
  у повтора того же содержимого (опрос без перемен): плитка не
  «прокручивается» на месте. Значки сравниваются по идентичности, `IconAt` —
  по коду функции.
- Профиль движения берётся у горутины, на которой идёт обновление: через
  `PostFor` и `Engine.Post` это цикл движка. Свой `StartMenu.Post` на чужой
  горутине `MotionRemote` не распознает.
- Заявлен только прямоугольник плитки; остальное меню не перерисовывается.
  `tileRectAbs` зажимает прокрутку, как отрисовка: после смены плиток на
  меньший набор заявка попадает на место плитки.
  При k = 0 композиция побайтно совпадает с кадром покоя прежнего состояния.
- Мгновенно: нулевая длительность темы (в том числе «меньше движения» и
  `MotionOff`), профиль `MotionRemote` (по сети переход не стоит кадров),
  вид без плиток, контекст без `OffscreenRenderer` или плитка, не
  помещающаяся в кадр.
- Переход шагает цикл движка дерева меню (`AnimateOwned` с меню-владельцем);
  закрытие меню и снятие подписки обрывают его.

Приёмка: средняя плитка Windows 10 при масштабе 150 % (150×150 физических) —
у запущенного движка (кадры только по повреждению) не больше 9 тайлов на
кадр смены и перехода, все тайлы касаются плитки — счёт по стоку кадров (тест
`TestLiveTileTrans_UpdateCostsAtMostNineTiles`, бенчмарки
`BenchmarkLiveTileTransitionFrame` и `BenchmarkLiveTileInstantUpdate`).

## Последствия

- Новый публичный API `desktop` (минорный номер).
- `Tile` по-прежнему несравним (`TileContent.IconAt` — функция); плитки
  сравниваются по `ID`, источники — только `sameSource` с защитой от паники.
- Новая служба владельца в `widget`: `OwnerPoster`, `PostFor`.
- Новая возможность контекста `OffscreenRenderer` (`core/draw`, `widget`).
- Источник обязан выдерживать вызов отписки из любой горутины и
  повторный `Subscribe` после отписки.
